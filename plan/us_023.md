# US-023: Accessibility

## Description
As a user with accessibility needs, I want the app to be fully usable with
screen readers and alternative input methods.

## Specifications

- All interactive elements have semantic labels / content descriptions.
- Button announces current state ("tap to write", "listening", "processing").
- Minimum touch target: 48dp (enforced by `minimumInteractiveComponentSize`).
- Error state changes announced to screen reader.
- All swipe gestures have equivalent button/tap alternatives:
  - Swipe-up to entry list = tap stats line.
  - Swipe-down to settings = tap settings icon.
  - Swipe-to-delete = custom accessibility action on list row.
  - Swipe-back from detail = back button.
- Respect system animation scale:
  - When set to 0 (reduce motion): disable pulse, fade, and shake animations.

## Reference

- `ui/main/ButtonArea.kt` — checks `ANIMATOR_DURATION_SCALE` for animation
  enable/disable, semantic `contentDescription` on button.
- `ui/entries/EntryListScreen.kt` — `customActions` for accessible delete.

## Acceptance Criteria

- [ ] VoiceOver (iOS) and TalkBack (Android) can navigate all screens.
- [ ] All interactive elements properly labeled.
- [ ] State changes announced to assistive technology.
- [ ] App fully usable without swipe gestures.
- [ ] Animations disabled when system reduce-motion is active.
