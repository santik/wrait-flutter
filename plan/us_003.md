# US-003: Encrypted Local Database

## Description
As a user, I want my diary entries stored in an encrypted local database so
that my data is protected even if my device is compromised.

## Specifications

- Use `sqflite_sqlcipher` or `drift` with SQLCipher encryption.
- Encryption key: random bytes generated on first launch, stored via
  `flutter_secure_storage` (Android Keystore / iOS Keychain backed).
- Entry table schema:
  - `id` INTEGER PRIMARY KEY AUTOINCREMENT
  - `raw_transcript` TEXT NOT NULL
  - `cleaned_text` TEXT (nullable)
  - `is_draft` INTEGER (0/1)
  - `language` TEXT NOT NULL
  - `created_at` INTEGER NOT NULL (epoch ms)
  - `word_count` INTEGER NOT NULL DEFAULT 0
  - `audio_path` TEXT (nullable)
- EntryRepository interface:
  - `getAllEntries()` returns reactive Stream<List<Entry>>
  - `getEntryById(id)` returns Entry?
  - `insertEntry(entry)` returns id
  - `updateWithCleanedText(id, cleanedText, wordCount)`
  - `deleteEntry(id)`
  - `getPendingDrafts()` returns List<Entry> (isDraft=true)
  - `deleteStaleDrafts()` — deletes drafts older than 7 days
  - `saveAudioDraft(audioPath, language)` returns id
  - `finalizeDraftWithCleanedText(id, rawTranscript, cleanedText, wordCount)`
  - `updateDraftTranscript(id, rawTranscript, wordCount)`
  - `updateEntryLanguage(id, language)`

## Reference

- `data/EntryEntity.kt` — Room entity fields.
- `data/EntryDao.kt` — Room DAO with query signatures.
- `data/WraitDatabase.kt` — SQLCipher + Tink AEAD encryption setup.
- `domain/repository/EntryRepository.kt` — repository interface.

## Acceptance Criteria

- [ ] Database is created encrypted; unreadable without key.
- [ ] CRUD operations work correctly.
- [ ] Key loss (factory reset) makes data unrecoverable (by design).
- [ ] Stream updates UI reactively when entries change.
- [ ] Stale drafts (>7 days) are deleted on app launch.
