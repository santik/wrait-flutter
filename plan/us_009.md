# US-009: Recording State Machine and Controller

## Description
As a developer, I want a recording state machine that orchestrates the full
recording pipeline (record, transcribe, cleanup, save).

## Specifications

- Recording states (sealed/union type):
  - Idle — ready to record.
  - Listening — actively recording audio.
  - Uploading — audio being sent to backend (Best mode only).
  - Processing — transcription/cleanup in progress.
  - Saved(entryId, detectedLanguage?) — entry saved successfully.
  - Error(error) — recording/processing failed.
  - Deleted(count) — entry(ies) deleted (triggered from list screen).
- `isActive` = Listening or Uploading or Processing.

- Controller logic on button tap:
  - Idle -> start listening.
  - Listening -> stop (if elapsed >= 5s) or error TooShort (if < 5s).
  - Uploading/Processing -> ignored (button disabled).
  - Saved -> start new recording.
  - Deleted -> start new recording.
  - Error(InsufficientPermissions) -> reset to Idle (let permission handler take over).
  - Error(other) -> start new recording (retry).

- Auto-clear timers:
  - Saved state: cleared after 4s (driven by UI).
  - Error/Deleted states: cleared after 3s (driven by controller).

- Mode-aware routing:
  - Best mode: check network availability first; use CloudTranscriptionService;
    after transcription call CleanupTranscriptUseCase.
  - Offline mode: check offline model availability; use on-device service;
    save raw transcript directly (no cleanup).

- On successful save: set `hasEverRecorded` flag.
- `shakeErrorKey`: counter incremented on TooShort/NoMatch errors for UI shake.

## Reference

- `MainRecordingController.kt` — full state machine with all transitions.
- `MainViewModel.kt` — exposes state to UI, handles retry and registration.
- `RecordingState` sealed class and `RecordingCountdownState` data class.

## Acceptance Criteria

- [ ] All state transitions match specification.
- [ ] Too-short recording (< 5s) produces TooShort error with shake key increment.
- [ ] Mode routing selects correct transcription service.
- [ ] Network/model availability checked before recording starts.
- [ ] State exposed as reactive stream for UI binding.
- [ ] Auto-clear timers reset state correctly.
