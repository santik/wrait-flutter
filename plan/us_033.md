# US-033: Horizontal Layout Fix

## Description
As a user holding the device horizontally, I want Wrait's primary recording and
entry-reading screens to remain usable without clipped controls, hidden
feedback, or overlapping content.

## Specifications

- Horizontal view must preserve access to the primary recording action, status
  feedback, quota text when present, and entry stats.
- Existing navigation and entry-management actions must remain usable in
  horizontal view:
  - stats to entry list
  - entry row to detail
  - entry deletion confirmation
  - detail share, delete, back, selection, and edit actions
- Layout must respect safe areas and platform system UI.
- Compact-height layouts must remain usable through appropriate content
  adaptation instead of hiding required actions.
- The fix must not regress existing portrait-phone behavior.

## Acceptance Criteria

- [ ] Main screen horizontal layout has no unintended clipping or overlap.
- [ ] Recording start/stop and state feedback are usable in horizontal view.
- [ ] Entry list rows remain readable, selectable, and deletable in horizontal
      view.
- [ ] Entry detail remains readable and all existing actions stay reachable in
      horizontal view.
- [ ] Permission prompts, confirmation dialogs, and transient feedback remain
      visible and actionable in horizontal view.
- [ ] Existing portrait layout behavior remains correct.
- [ ] Automated tests cover horizontal layout behavior.
- [ ] Android emulator and iOS simulator validation evidence is recorded unless
      an explicit validation exception is approved during planning.
