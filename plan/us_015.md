# US-015: Draft Retry System

## Description
As a user, I want failed recordings to be saved as drafts and automatically
retried on next app launch.

## Specifications

- Draft creation (during recording failure in Best mode):
  - Network/timeout/backend errors: save audio file path as audio draft.
  - Transcription succeeded but cleanup failed: save raw transcript as text draft.
- On app launch (Best mode only, after device registration):
  1. Delete stale drafts (> 7 days old).
  2. Load pending drafts (isDraft=true), sorted by createdAt descending.
  3. For each audio draft (audioPath != null):
     - Call `transcribeAudioDraft(audioPath)`.
     - On transcription success: attempt cleanup.
     - On cleanup success: finalize entry with cleaned text, delete audio file.
     - On cleanup failure: promote to text draft (save raw transcript, delete audio).
     - On transcription failure: leave as audio draft.
  4. For each text draft (rawTranscript present, no audioPath):
     - Call cleanup use case.
     - On success: update entry with cleaned text.
     - On failure: leave as text draft.
- Runs in background, does not block UI or app launch.
- Detected language from retry transcription updates entry language if different.

## Reference

- `MainViewModel.kt` methods: `retryPendingDrafts()`, `retryAudioDraft()`,
  `retryTextDraft()` — full retry logic with audio-to-text promotion.

## Acceptance Criteria

- [ ] Audio drafts retried and finalized on success.
- [ ] Text drafts retried and cleaned on success.
- [ ] Failed retries leave drafts intact for next launch.
- [ ] Stale drafts (>7 days) deleted automatically.
- [ ] Audio files deleted after successful transcription.
- [ ] Retry runs in background without blocking app startup.
- [ ] Language updated if detected language differs from original.
