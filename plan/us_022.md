# US-022: Analytics Tracking

## Description
As a developer, I want analytics events tracked for key user actions to
understand app usage and diagnose issues.

## Specifications

- AnalyticsTracker interface with `trackSafely` wrapper that catches and logs
  any tracking exceptions (analytics must never crash the app).
- Key events:
  - `app_opened` (privacyMode, entryCount)
  - `recording_started` (privacyMode, language)
  - `transcription_succeeded` (privacyMode, detectedLanguagePresent, savePath)
  - `cleanup_succeeded` (privacyMode, savePath)
  - `cleanup_failed` (privacyMode, savePath, reason)
  - `entry_saved` (privacyMode, savePath: Direct or Retry)
  - `draft_retry_started` (draftType: Audio or Text)
  - `draft_retry_succeeded` (draftType)
  - `draft_retry_failed` (draftType, failureStage, errorType)
  - `privacy_mode_toggled` (from, to)
  - `microphone_permission_requested`
  - `microphone_permission_denied`
  - `microphone_permission_permanently_denied`
  - `entries_list_opened` (entryCount)
  - `entry_shared`
  - `entry_deleted`
- Implementation: pluggable (Firebase Analytics, or no-op for tests).

## Reference

inside `wrait-android/src/main/java/com/wrait/app` directory
- `analytics/AnalyticsTracker.kt` — interface and `trackSafely` extension.

## Acceptance Criteria

- [ ] All events fire at correct moments in the user flow.
- [ ] Analytics exceptions never propagate to UI or crash app.
- [ ] Tracker is injectable and replaceable with no-op for tests.
