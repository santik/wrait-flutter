# US-028: Fix Device Registration Launch Integration Tests

## Description
As a developer, I want the device-registration launch integration tests to pass
on a real Android phone so that `deploy_debug.sh` can complete the real-device
test phase and install the Flutter app only after the launch flow is verified.

## Specifications

- Investigate the real-device failures in
  `integration_test/device_registration_launch_flow_test.dart`.
- Update the tests and/or launch-screen expectations so they match the current
  Flutter app UI and launch behavior on a real Android phone.
- Preserve the existing intent of the tests:
  - launch registration remains non-blocking
  - successful registration updates the in-memory session quota
  - transient registration failures preserve the existing quota
  - stored device ID reuse still works across launches
- Keep the fix scoped to the failing launch-registration integration coverage
  unless investigation proves the production launch flow is actually wrong.
- Re-run the real-device integration path through `./deploy_debug.sh` after the
  fix.
