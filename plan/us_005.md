# US-005: Backend API Client

## Description
As a developer, I want an HTTP client for the wrait backend so that the app
can register devices, transcribe audio, and clean up transcripts.

## Specifications

- Use `dio` for HTTP.
- Base URL from environment config (default: https://wrait-backend.vercel.app).
- All requests include:
  - `X-Device-Id` header.
  - `X-Proxy-Secret` header (from env config).
- Endpoints:
  1. `POST /api/register` — RegistrationResult (success with quota, or failure).
  2. `POST /api/transcribe` (multipart: audio file + language) —
     TranscriptionResult (transcript, detectedLanguage, quota).
  3. `POST /api/cleanup` (JSON: transcript, language) —
     CleanupResult (cleanedText, quota).
- RecordQuotaState model: `{limit, count, remaining, resetAt}`.
  - Validate: limit >= 0, count >= 0, remaining >= 0, count <= limit,
    remaining <= limit. Invalid quota returns null (preserve last valid value).
- Error mapping:
  - Network timeout -> specific error type.
  - HTTP 401 -> ProxyAuthFailed.
  - HTTP 5xx -> BackendUnavailable.
  - IOException -> NoInternet.
- Registration: retry up to 3 times with exponential backoff.

## Reference

## Acceptance Criteria

- [ ] Registration call succeeds against real/mock backend.
- [ ] Transcription uploads audio and returns transcript + detected language.
- [ ] Cleanup returns cleaned text.
- [ ] Quota parsed and validated correctly.
- [ ] Errors mapped to correct failure types.
- [ ] Unit tests with mocked HTTP cover all error cases.
