# US-027: Android Deploy Script and App Namespace Isolation

## Description
As a developer, I want a simple way to deploy the Flutter app to Android
without overwriting the existing Wrait Android app already installed on the
device.

## Specifications

- Add Android deployment script support for this Flutter project.
- Use `wrait-android/deploy_debug.sh` and `wrait-android/deploy.sh` as the
  reference workflows for the new Flutter-side script design.
- Provide a debug deployment flow that builds and installs the Flutter Android
  app onto a connected emulator or physical device.
- Fail with a clear message when no Android target is connected or selectable.
- Change the Android app identity so the Flutter app does not overwrite the
  existing Wrait app during install.
- Rename the Android namespace / package identity from `com.wrait.app` to a
  `wrait-flutter` aligned value such as `com.wrait.flutter`, updating all
  required source, manifest, Gradle, and script references consistently.
- Keep the deployment workflow simple enough to run as a regular developer
  command from the repo.

## Reference

inside sibling `wrait-android` project
- `deploy_debug.sh` — reference for debug deployment flow.
- `deploy.sh` — reference for standard deployment flow.

## Acceptance Criteria

- [ ] A single developer command can deploy the Flutter app to a connected
      Android emulator or device.
- [ ] The deployed Flutter app installs alongside the existing Wrait Android
      app instead of replacing it.
- [ ] The deployment script reports a clear error when no Android target is
      available.
- [ ] Android namespace / package identity updates are applied consistently
      wherever required for build and install.
