# US-007: Cloud Transcription Service (Best Mode)

## Description
As a user in Best mode, I want my audio uploaded to the backend for high-quality
transcription.

## Specifications

- CloudTranscriptionService implements TranscriptionService.
- Flow:
  1. Start audio recording, emit RecordingStarted status with hard cap deadline.
  2. On user stop, emit Uploading status.
  3. Upload audio file to `/api/transcribe` via backend client.
  4. On success: return TranscriptionResult.Success(transcript, detectedLanguage, quota).
  5. On failure: return TranscriptionResult.Failure(reason, audioDraftPath).
- Failure reasons: Network, Timeout, BackendUnavailable, ProxyAuthFailed, ApiError.
- Detected language normalization: convert underscores to hyphens, validate via
  Locale parsing, resolve to supported language code.
- Audio file saved as draft path on failure (for retry in US-015).

## Acceptance Criteria

- [ ] Audio uploaded successfully in Best mode.
- [ ] Transcript and detected language returned correctly.
- [ ] On network failure, audio file path preserved for draft retry.
- [ ] Detected language correctly normalized (e.g. "en_US" becomes "en-US").
- [ ] Status callbacks fire in correct order (RecordingStarted, Uploading).
