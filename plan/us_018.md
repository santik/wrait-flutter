# US-018: Error Handling and User Feedback

## Description
As a user, I want clear, actionable feedback when something goes wrong.

## Specifications

- Error-to-text mapping (displayed in status line):
  | Error | Status Text |
  |-------|-------------|
  | TooShort | "too short / keep talking" |
  | NoMatch | "nothing caught / too quiet?" |
  | InsufficientPermissions | "mic blocked / tap to open settings" |
  | ConnectionRequired | "best mode needs connection" |
  | NotAvailable(lang) | "no offline model for {displayName}" |
  | NoInternet / Network / Timeout | "no connection / saved as draft" |
  | BackendUnavailable | "service unavailable / saved as draft" |
  | ProxyAuthFailed | "server config error / saved as draft" |
  | ApiFailed (default) | "saved as draft / will retry" |
- Shake animation: horizontal oscillation (-6, +6, -4, +3, 0 px over ~310ms)
  triggered on TooShort and NoMatch errors.
- Error states auto-clear to Idle after 3 seconds.
- Toast/snackbar for non-blocking messages (e.g. "Couldn't save language settings").

## Reference

- `ui/main/MainScreen.kt` `statusTextFor()` — complete error-to-text mapping.
- `ui/main/ButtonArea.kt` — shake animation keyframes in LaunchedEffect.
- `MainRecordingController.kt` — `emitError()` with auto-clear delay.

## Acceptance Criteria

- [ ] All error states show correct user-friendly message.
- [ ] Shake animation fires for TooShort and NoMatch only.
- [ ] Draft-saving errors reassure user that data is preserved.
- [ ] Permission errors provide actionable link to settings.
- [ ] Error states auto-clear after 3 seconds.
