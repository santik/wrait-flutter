# US-026: Integration Testing

## Description
As a developer, I want automated tests covering the core recording flow and
data layer to catch regressions.

## Specifications

- Widget tests:
  - Main screen renders all recording states with correct labels.
  - Entry list renders entries and handles empty state.
  - Entry detail renders text, share action, delete action.
  - Settings panel toggle.
- Integration tests (with mocked services):
  - Full Best mode recording flow: tap -> listen -> stop -> upload -> cleanup -> saved.
  - Too-short recording produces error.
  - Draft save on network failure.
  - Draft retry on next launch.
  - Database CRUD operations with encrypted DB.
- Mock/fake implementations:
  - FakeTranscriptionService — returns configurable results.
  - FakeBackendClient — returns canned HTTP responses.
  - FakeAudioRecorder — no-op recording.
- Test recording state machine transitions exhaustively.

## Reference

- `androidTest/` directory — existing instrumented tests for
  MainRecordingController, MainViewModel, database migrations, full journey.

## Acceptance Criteria

- [ ] Core Best mode recording flow tested end-to-end with mocks.
- [ ] State machine transitions tested for all paths.
- [ ] Database CRUD operations verified.
- [ ] Widget tests cover all visible states.
- [ ] Tests pass on CI for both platforms.
